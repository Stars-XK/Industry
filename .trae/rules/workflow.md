# Trae AI Rules

## Workflow Rules

- **Code Commit and Merge**: 每当到达一定阶段或完成特定任务步骤时，必须自动将代码提交，并将其合并到主分支 (main)。
- **里程碑同步与进度追踪**: 每次完成 `Development_Roadmap.md` 中的一个模块或里程碑时，必须主动去更新该文档中的任务状态（将 ⬜ 改为 ✅），并在该步骤的 Git Commit Message 中明确标明进度更新。

## Development Rules

- **模块化与高复用原则**: 在编写新功能前，先检查是否已有可复用的组件或方法。能公共使用的功能必须抽取为公共代码，严禁复制粘贴。前端必须维护统一的业务组件库。
- **代码拆分与细粒度控制**: 
  - 前端：当单个组件代码量过多（如超300行），或包含多个独立视图区域（如搜索区、表格区、弹窗区）时，必须将其拆分为多个子组件。
  - 后端：当单个方法代码量过大或包含复杂业务流转时，必须提取成多个具有“单一职责”的私有方法或独立的 Helper 类。
- **类型安全与命名规范**: 前后端严格使用 TypeScript，严禁滥用 `any`。遵循标准的 `PascalCase`, `camelCase`, `snake_case` 命名约定。
