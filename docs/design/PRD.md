# 信创工业综合治理平台 - 需求文档 (PRD)

## 1. 总体目标
构建一个符合国家信创标准的工业级综合治理平台。平台整合水务、电力、能耗、环境品质、安防门禁、资产运维、房屋、天气、地理、AI等多维数据，提供百亿级时序数据的处理与多级清洗聚合能力，在边缘计算、物联网（IoT）、毫秒级设备反控及全场景AI主动预测（以水务为核心）方面提供卓越体验。同时，系统底层需具备完备的安全性与商业权益保护（防欠款）机制。

## 2. 核心模块需求

### 2.1 综合业务监控与管理
- **水务（重中之重）**：实时监控水消耗、管网状态。**重点实现水务用量分析、用量预测、爆管预警等主动预测性功能，防患于未然。**
- **电力与能耗**：工业级能耗分析，多级计量单元的实时监测。
- **空间与环境品质管理**：深度监测室内/密闭工业场景的湿度、PM2.5、CO2浓度及特定有害气体。
- **安防与门禁监控**：整合AI视频监控、门禁刷卡记录及消防火灾报警数据。
- **房屋与地理**：BIM/GIS融合，实现资产与地理空间信息的三维可视化管理。
- **天气**：气象数据接入，为预警和生产调度提供环境支撑。

### 2.2 运维治理与业务闭环 (执行层)
- **报警收敛与根因分析（RCA）**：建立工业级的“报警风暴压制”机制。基于设备与管网的拓扑关系，在短时间内发生大面积连锁报警（如主管道爆管导致下游全面水压报警）时，自动进行报警合并与收敛，并通过根因分析算法提取出核心故障点，避免无效工单轰炸。
- **设备资产全生命周期台账**：建立设备静态与动态资产档案（如采购批次、过保时间、历史维修记录、备品备件库存等）。
- **人员与资产定位**：结合室内外定位技术（如UWB、蓝牙或GIS）与门禁轨迹，实现人员、特种车辆及移动高价值资产的实时位置追踪。
- **巡检与工单流转系统**：
  - **智能巡检**：支持制定周期性或基于AI预测触发的动态巡检计划，支持移动端扫码/NFC打卡执行。
  - **工单流转**：将“时序预警”、“AI预测”与“巡检异常”转化为标准工单，实现**预测性维护的自动化派单闭环**（创建-接单-执行-验收-评价）。
- **统一消息与通知引擎**：构建多渠道（短信、邮件、App推送、企微/钉钉等）告警与通知机制。在水务爆管等紧急事件发生时，结合“人员定位”，将紧急工单与通知秒级推送给距离最近的可调度人员。

### 2.3 数据中台与治理（百亿级数据架构）
- **海量时序与多源异构接入**：支持时序数据高并发接入；同时针对**设备、站点、测点、分区**等基础业务模型，提供全渠道、标准化的数据接入能力（支持 MQ、Kafka、HTTP 接口调用、文件批量导入等），确保第三方厂家或外部系统能无缝对接与开箱即用。
- **数据质量保障（断点插值与离线判定）**：为保障上层建筑与层级统计的数据连续性，引入数据补偿机制：
  - **短期断点**：对于网络波动等造成的短期数据缺失，系统在清洗阶段自动进行**数据插值与拟合补偿**（如参考临近时间点或历史同期均值）。
  - **离线判定**：当设备数据中断**超过 1 天**时，直接判定设备为“离线故障”状态，停止该节点的数据插值补偿，并向上层抛出设备异常工单。
- **数据清洗与标准化**：依托**独立的时序数据库（如 TDengine 等）自带的流计算引擎**进行数据清洗，将海量原始数据**标准化聚合为 1分钟、5分钟、1小时** 等多时间维度的数据。
- **元数据同步与流计算标签映射**：由应用层（NestJS服务）定时将 PG 库中的分区、站点、测点等层级配置信息同步至时序数据库，并作为**标签（Tag）**存储。流计算引擎基于这些 Tag，高效实现**设备级别**与**分区/区域级别**的双重粒度聚合。
- **冷热数据分级存储与无缝查询**：针对百亿级历史数据，利用时序数据库自带的分级存储能力（如 TDengine 的多级存储）：
  - **热数据**：近 1 年的高频时序数据存储在高性能固态盘（SSD）中，保障秒级统计与监控查询。
  - **冷数据归档**：超过 1 年的原始数据自动归档降级至廉价的机械盘（HDD）或信创对象存储（如国产 MinIO）中。
  - **查询透明**：**冷热分离对应用层完全透明**。前端或分析模型查询历史数据时，依然通过统一的 SQL/API 接口拉取，时序库底座会自动跨冷热介质进行数据检索。
- **数据治理**：元数据管理、数据质量监控与细粒度权限管控。

### 2.4 物联网(IoT)与边缘计算
- **边缘与云端弹性协同接入**：为适应不同地区网络与硬件条件，系统支持双重接入模式：
  1. **边缘计算模式**：边缘节点本地解包、清洗与过滤，通过 MQTT 标准化上报云端（降本增效）。
  2. **云端直传模式**：设备原始报文直接透传至云端网关服务进行处理。
- **协议兼容**：全面支持主流工业协议（如MQTT, OPC UA, Modbus等），实现海量设备的高可用连接。
- **设备反控**：追求 **毫秒级** 的超低延迟云边协同反控机制，保障生产安全与指令的精确执行。

### 2.5 AI 综合赋能场景
- **核心AI（水务优先）**：用水量深度分析、用量预测、爆管等异常事件的提前主动预测。
  - **爆管预测核心模型**：基于 GIS 地理范围，综合分析**管网压力、瞬时流量、水质参数以及夜间最小流量（MNF）**等多维度指标的突变与趋势，建立高精度的漏损与爆管预测模型。
- **通用AI场景**：能耗趋势预测、设备预测性维护、安防与工业视频监控视觉分析。
- **大模型赋能**：基于大模型的智能调度策略生成与辅助决策。

### 2.6 系统边界与商业保护机制
- **系统核心边界（非计费系统）**：本平台聚焦于工业综合治理中的**“用量统计、数据分析与态势展示”**，通过分析辅助决策。平台**坚决不涉及计费、费用结算与财务资金流**，以避免引入高昂的数据回滚、冲账及合规性风险。
- **系统安全**：全方位的平台安全防护策略（网络、数据传输、应用访问等）。
- **商业权益保护（防欠款策略）**：采用**动态 License 授权码**机制。该机制仅在应用层（如 Web 页面访问、手动下发反控指令）进行拦截与弹窗提示，**绝不影响底层主干业务计算、数据采集及核心流式清洗任务**的正常运行。

## 3. 系统架构与技术选型规划

### 3.1 前后端架构设计
- **前端架构**：采用**单体大前端架构**（Monolithic Frontend），集中管理全维度的业务视图与交互，确保用户体验的一致性与数据联动的流畅性。
- **后端架构**：采用基于 **NestJS** 框架的分布式微服务架构。
  - **服务拆分原则**：按大业务领域进行粗粒度拆分，如“报警中心服务”、“数据中台服务”、“设备接入网关服务”、“业务调度服务”等。
  - **部署与扩容**：各个微服务完全解耦，支持根据业务负载进行**独立的服务器部署与横向扩容**（例如，在数据洪峰时单独为“数据中台服务”增加服务器）。
  - **服务治理**：利用 **Redis** 作为核心的服务注册中心与状态监控中枢。
  - **高可用与自愈**：各微服务通过 Redis 维持心跳，当监控到服务超时或无响应时，触发自动重启/熔断机制，保障系统在复杂工业环境下的极高可用性。

### 3.2 信创适配要求
- **底层硬件**：暂无特定厂商要求，保持通用性与可扩展性。
- **操作系统**：以 **麒麟操作系统（Kylin）** 为主。
- **数据库（解耦设计）**：
  - **基础业务库**：采用 **PostgreSQL (PG)** 存储设备台账、组织架构、业务配置等关系型基础数据，方便后续向其他纯信创关系库平滑移植。
  - **时序与大数据库**：采用 **独立的时序数据库（如 TDengine / IoTDB 等）** 专职处理百亿级高频时序监控数据，并充分利用其内置流计算能力进行降采样与清洗聚合。
- **缓存与中间件**：
  - **Redis**：不仅用于业务缓存，更作为后端微服务的心跳监控与服务注册中枢。
  - 按需引入其他主流信创组件。
