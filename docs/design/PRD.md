# 信创工业综合治理平台 - 需求文档 (PRD)

## 1. 总体目标
构建一个符合国家信创标准的工业级综合治理平台。平台整合水务、电力、能耗、环境品质、安防门禁、资产运维、房屋、天气、地理、AI等多维数据，提供百亿级时序数据的处理与多级清洗聚合能力，在边缘计算、物联网（IoT）、毫秒级设备反控及全场景AI主动预测（以水务为核心）方面提供卓越体验。同时，系统底层需具备完备的安全性与商业权益保护（防欠款）机制。

## 2. 核心模块需求

### 2.1 综合业务监控与管理
- **水务（重中之重）与 DMA (独立计量区域) 漏损管理**：
  - **全域 GIS 管网空间映射与水力拓扑**：导入城市级/厂区级水管网 GIS Shapefile 矢量数据，将地下给排水管线、水厂、二供泵房、加压泵站等设施进行空间落图与拓扑连通性关联。
  - **GIS 地图动态交互与报警联动**：在地图上直观悬浮显示每个压力点、流量点的实时数值与流向。利用管线颜色渐变呈现流速/压力分布。若出现压力骤降或流速激增异常，对应管段与测点在地图上立即高亮闪烁，并联动右侧面板快速展示报警详情与现场视频，实现“一图统管”。
  - **多级 DMA 分区与产销差 (NRW) 实时结算**：支持从厂区级到车间级、楼层级的一、二、三级 DMA 网格化虚拟切分。系统基于国际水协 (IWA) 标准水量平衡表，实时计算供水量、售水量、表观漏损与真实漏损。
  - **多维产销差与水量统计报表**：提供强大的报表引擎，一键快速查看特定分区的供水量、售水量、产销差及漏损率。支持报表数据的**上下级穿透下钻**（点击父分区展开子分区明细），并支持任意数据维度的前后月份（环比）、历史同期（同比）叠加曲线比对，直观暴露异常用水波动。
  - **夜间最小流量 (MNF) 智能暗漏排查**：在每日凌晨（如 2:00-4:00）用户用水低谷期，系统自动提取各 DMA 分区的最小流量基线。结合 AI 剔除合法夜间生产用水后，精准量化区域“背景暗漏水量”。一旦 MNF 连续 3 天偏离动态基线，自动向外勤派发“听漏探漏”工单。
  - **基于水力模型的“声水”交叉精准定位**：系统深度融合微观管网水力模型（如 EPANET 算法）与声学物联网设备（智能听漏仪/相关仪）。当水动力学（流量突增/压力骤降）出现异常时，系统自动调取该区域的声学频段数据进行空间交叉比对，实现物理漏水点的 **米级精准定位**。
  - **主动压力调控减漏 (PRV 联动)**：针对地形高差大或夜间压力冗余的管网区域，系统根据实时流量与末端压力反馈，**自动毫秒级反控管网中的智能减压阀 (PRV)**。在用水低谷期主动降低管网运行压力，从物理源头上减少漏水量并极大地降低爆管概率。
  - **用量分析与预测**：支持按日、周、月维度生成用水报表，并结合历史同环比、节假日及天气因素，利用时序预测算法（如ARIMA、LSTM等）对未来用水量进行预测。
  - **大用户监控与“表观漏损”挽回**：针对高耗水特种设备或工业用水大户建立独立监控档案。AI 智能比对水表口径与实际流量曲线，精准识别“大表小用”（导致始动流量不计费）或水表倒转、违规偷水行为，推送水表降级/升级建议，挽回水费流失。
  - **爆管预警与 GIS 爆管关阀寻址**：一旦AI模型输出爆管高风险预警（置信度>85%），系统自动截取前后30分钟压力、流量曲线，并在10秒内生成带GIS坐标的紧急工单。**（GIS亮点功能）** 系统基于管网连通性拓扑分析，自动计算并高亮显示**需要关闭的最近 N 个上游/下游控制阀门（停水影响分析）**，并将阀门列表推送至抢修人员及周边受影响的用户（车间/居民）。
- **电力与能耗**：工业级能耗分析，多级计量单元的实时监测。
  - **异常用电诊断与“窃电/漏电”识别**：建立车间级电量平衡模型（总表与分表比对）。当线损率突增或非生产时段（如夜间、节假日）出现异常用电基线偏移时，系统自动识别潜在的“设备空转”、“漏电”或“违规用电”行为，并推送节能整改工单。
  - **峰谷平电价需量优化**：结合当地电网的分时电价政策与历史负荷数据，AI 推荐最优的生产设备排班计划（如将高耗能设备自动调度至谷电时段运行），实现智能降本。
- **空间与环境品质管理**：深度监测室内/密闭工业场景的湿度、PM2.5、CO2浓度及特定有害气体。
  - **受限空间“窒息/中毒”主动干预**：针对地下管廊、密闭储罐等高危空间，若有害气体（如硫化氢、一氧化碳）浓度逼近安全阈值下限，且门禁系统检测到内部有人，系统将**自动联动开启大功率排风新风系统**，并锁死进入门禁，触发声光报警与人员撤离广播。
- **安防与门禁监控**：整合AI视频监控、门禁刷卡记录及消防火灾报警数据。
  - **全景安防数字沙盘 (BIM/GIS融合)**：将视频流投射或挂载到 3D 建筑模型的墙面/空间内（Video-in-3D），实现“所见即所得”的空间安防巡检；在警情发生时，摄像机视锥体自动变红，直观展示盲区。
  - **AI 视觉越界与“一人一卡”防尾随**：利用边缘 AI 摄像头识别关键设备区（如高压配电房、水泵核心区）的异常闯入。联动门禁数据，若刷卡记录为 1 人，但 AI 视觉识别进入 >1 人，立即触发“尾随报警”并截取现场 15 秒视频推送安保中心。
  - **火情初期秒级联动封控**：接收到烟感/温感报警后，系统自动调用最近的摄像头对准起火点进行二次视觉确认；确认后，联动切断非消防电源、打开消防通道门禁、启动排烟，并向对应楼层发布疏散指令。
- **房屋与地理**：BIM/GIS融合，实现资产与地理空间信息的三维可视化管理。
  - **基于 BIM 的“盲穿”地下管线透视与安全间距分析**：在发生如“地面塌陷”、“施工挖掘”等事件前，通过移动端 AR 技术或 PC 端 BIM 剖视，精准透视地下暗埋的水、电、气管网走向，防止二次施工造成的管线挖断事故。提供“安全间距分析”，若施工动土范围与高压电缆、燃气管线空间距离 <1 米，直接锁定施工审批。
- **天气**：气象数据接入，为预警和生产调度提供环境支撑。
  - **极端气象“防汛/防冻”前置调度**：对接气象局数据，当预测到未来 24 小时内有暴雨或台风时，系统自动生成“防汛排涝预案”（如提前抽空雨水调蓄池、检查排水泵状态）；若预测有极端寒潮，提前触发“防冻保温工单”（如裸露水管伴热带巡检）。

### 2.2 运维治理与业务闭环 (执行层)
- **报警收敛与根因分析（RCA）**：建立工业级的“报警风暴压制”机制。基于设备与管网的拓扑关系，在短时间内发生大面积连锁报警（如主管道爆管导致下游全面水压报警）时，自动进行报警合并与收敛。
  - **算法应用逻辑**：通过图数据库（或PG的递归查询）维护管网拓扑树，当同一拓扑树下3分钟内触发>5个相关报警时，自动收敛为1个“父级综合报警”，并通过根因分析算法提取出上游核心故障点，避免无效工单轰炸。
- **设备资产全生命周期台账**：建立设备静态与动态资产档案（如采购批次、过保时间、历史维修记录、备品备件库存等）。
- **人员与资产定位**：结合室内外定位技术（如UWB、蓝牙或GIS）与门禁轨迹，实现人员、特种车辆及移动高价值资产的实时位置追踪。
- **巡检与工单流转系统**：
  - **智能巡检**：支持制定周期性或基于AI预测触发的动态巡检计划，支持移动端扫码/NFC打卡执行。
  - **工单流转**：将“时序预警”、“AI预测”与“巡检异常”转化为标准工单，实现**预测性维护的自动化派单闭环**（创建-接单-执行-验收-评价）。
  - **SLA超时升级机制**：对工单的各个环节（如接单超时、处理超时）设置SLA阈值，超时自动升级并抄送至上级管理者。
- **统一消息与通知引擎**：构建多渠道（短信、邮件、App推送、企微/钉钉等）告警与通知机制。在水务爆管等紧急事件发生时，结合“人员定位”，将紧急工单与通知秒级推送给距离最近的可调度人员。

### 2.3 数据中台与治理（百亿级数据架构）
- **海量时序与多源异构接入**：支持时序数据高并发接入；同时针对**设备、站点、测点、分区**等基础业务模型，提供全渠道、标准化的数据接入能力（支持 MQ、Kafka、HTTP 接口调用、文件批量导入等），确保第三方厂家或外部系统能无缝对接与开箱即用。
- **数据质量保障（断点插值与离线判定）**：为保障上层建筑与层级统计的数据连续性，引入数据补偿机制：
  - **短期断点（插值规则）**：对于网络波动等造成的缺失（如<3小时），系统在清洗阶段自动使用**线性插值法**或**前值填充**进行补偿，插值数据需打上专门的标签（如`is_interpolated=true`）以区分真实数据。
  - **离线判定**：当设备数据中断**超过 1 天**时，直接判定设备为“离线故障”状态，停止该节点的数据插值补偿，并向上层抛出设备异常工单。
- **数据清洗与标准化**：依托**独立的时序数据库（如 TDengine 等）自带的流计算引擎**进行数据清洗，将海量原始数据**标准化聚合为 1分钟、5分钟、1小时** 等多时间维度的数据。
  - **离散累积量推算瞬时与日用量算法（重点业务场景）**：针对水务及工业现场中依靠电池供电、低频非连续上报的远传水表（如 NB-IoT/LoRa，可能几小时甚至几天才上报一次累积底度），系统内置高级数据插值与推算引擎：
    1. **整点基准重构**：利用**单调三次样条插值（PCHIP）或线性插值算法**，将不规则、离散的上报时间点数据，强制对齐并推算出每个整点（如 `01:00:00`, `00:00:00`）的虚拟累积量。
    2. **小时/日用量生成**：通过计算相邻整点（如今日0点与次日0点）的虚拟累积量差值，精准还原出“每小时用量”与“每日供水量”。
    3. **瞬时流速模拟**：当上报间隔极长时，单纯的线性插值会抹平昼夜峰谷。系统引入**基于历史日用水变化曲线（Diurnal Curve）的加权分配法**，将两次离散上报间的总水量，按历史该站点的昼夜用水权重分配到各个小时，从而推算出贴近真实物理规律的“虚拟瞬时流速”。
  - **异构设备表计异常容错与标准化**：针对底层设备上报类型的复杂性（有的只报累积量，有的报瞬时量，有的报日用量），系统提供内置的数据换算算子。除了基础的累积量转瞬时量外，系统具备强大的边界容错机制：
    1. **表计翻转（Rollover）补偿**：当机械水表或数字表达到最大量程归零时，算法自动识别出巨大的负差值，并加上表计量程进行接续补偿（`当前值 - 上次值 + 最大量程`）。
    2. **负压倒转过滤**：受管网压力波动影响造成的微小累积量回退，算法通过强制单调递增约束进行过滤剔除。
    3. **超物理极限跳变剔除**：通过计算相邻两点的变化率，若推算出的流速超过了该管径设计的物理最大流速阈值，直接判定为脏数据并予以剔除。
  - **售水营收数据融合与清洗**：考虑到多数售水量数据来自外部“营收计费系统”或大用户抄表系统（多为按月/双月出账的非连续数据），系统通过 API 接口或前置机中间库定时同步营收数据。接入后通过数据中台进行“营收与实时供水对齐”清洗（如剔除重复账单、空值补偿、并按特定折算算法将月度营收账单平滑分摊到每日/每小时），确保“产销差 (供水 - 售水)”计算在相同的时间维度上具备可比性。
  - **聚合规则配置**：支持对不同类型的指标配置不同的聚合函数（如流量使用`sum`，温度使用`avg`，压力使用`max`/`min`）。
- **元数据同步与流计算标签映射**：由应用层（NestJS服务）定时将 PG 库中的分区、站点、测点等层级配置信息同步至时序数据库，并作为**标签（Tag）**存储。流计算引擎基于这些 Tag，高效实现**设备级别**与**分区/区域级别**的双重粒度聚合。
- **冷热数据分级存储与无缝查询**：针对百亿级历史数据，利用时序数据库自带的分级存储能力（如 TDengine 的多级存储）：
  - **热数据**：近 1 年的高频时序数据存储在高性能固态盘（SSD）中，保障秒级统计与监控查询。
  - **冷数据归档**：超过 1 年的原始数据自动归档降级至廉价的机械盘（HDD）或信创对象存储（如国产 MinIO）中。
  - **查询透明**：**冷热分离对应用层完全透明**。前端或分析模型查询历史数据时，依然通过统一的 SQL/API 接口拉取，时序库底座会自动跨冷热介质进行数据检索。
- **数据治理**：元数据管理、数据质量监控与细粒度权限管控。

### 2.4 权限管控与系统安全
- **多维组织架构与数据权限 (RBAC+)**：
  - **基于“部门-人员-角色”的细粒度授权**：支持集团、厂区、车间多级划分。数据权限严格按组织层级与分区挂钩，支持**“仅本人可见”、“本部门可见”、“本部门及下级可见”、“全部可见”或“指定特定 DMA 分区/站点可见”**的行级数据权限隔离。
- **细粒度功能与界面权限拦截**：
  - **界面与按钮级控制**：从宏观的左侧页面菜单，到微观的单个操作按钮（如“导出报表”、“修改阈值”、“强制关阀”），甚至是某个数据图表面板的可见性，均可通过角色进行配置。
  - **接口级鉴权**：前后端分离架构下，所有微服务 API 调用均强制校验 Token 及对应资源的操作权限，防止越权调用。
- **安全审计与日志**：
  - 核心业务操作（如反控指令下发、阈值修改、角色分配）必须记录详尽的审计日志（包含操作人、时间、IP、修改前/后数值）。
- **数据脱敏**：针对人员手机号、敏感资产信息，在前端展示时进行星号掩码脱敏，仅特权角色可见明文。

### 2.4 工业级 SCADA 深度融合与控制中枢
系统不仅是数据的“展示层”，更向下全面兼容并替代部分传统 SCADA（数据采集与监视控制系统）功能，成为整个工业现场的控制中枢。

- **多源异构协议采集与反控**：
  - **无缝对接底层 PLC/DCS**：支持直接读取西门子、施耐德、三菱等主流 PLC 及 DCS 系统的寄存器点位（兼容 OPC UA/DA、Modbus RTU/TCP、IEC 104、Profinet 等协议）。
  - **毫秒级云边协同反控**：突破传统云平台“只监不控”的弱点，依托边缘网关实现 **<100ms** 的闭环控制。支持工艺流程的远程启停、泵阀开度无级调节（PID 设定），并具备**“写前校验”与“执行反馈”**的双向握手机制，保障生产指令绝对安全。
- **纯 Web 化工业组态与动态交互**：
  - **拖拽式 2D/2.5D 工艺流程组态**：内置符合 ISA 规范的工业图元库（泵、阀、储罐、管道等）。业务人员可零代码搭建车间级工艺流程图。
  - **数据驱动的动态图元**：图元状态与底层时序数据 Tag 深度绑定（如：管道根据流速呈现流动动画，电机根据频率变色，液位计实时升降），实现“所见即所得”的工艺映射。
- **高级报警与安全联锁 (Interlock)**：
  - **多维度分级报警**：支持高高报(HH)、高报(H)、低报(L)、低低报(LL)及偏差报警的灵活配置。
  - **软联锁与自动保护**：在 SCADA 软件层配置因果矩阵（Cause & Effect）。当关键参数越限（如水池液位逼近溢流线），系统不依赖人工干预，自动触发联锁动作（如强制关停上游进水泵），防止生产事故。
- **工业配方管理 (Recipe Management)（批次生产场景）**：
  - 针对需要批量生产或水质加药调配的场景，支持**多版本配方参数集**的创建、审核与下发。
  - 换线或调整工艺时，系统将配方（如目标流量、加药比例、搅拌时间）一键下发至底层 PLC。下发过程包含严格的设备物理边界校验，并记录带有电子签名的合规审计日志（防篡改），实现生产批次的端到端追溯。
- **边缘与云端弹性协同接入**：
  1. **边缘计算模式**：边缘节点（如工业树莓派/信创网关）本地解包、清洗与过滤，通过 MQTT 标准化上报云端；在断网情况下，边缘节点可独立执行本地保护策略（如压力超限自动关阀）。
  2. **云端直传模式**：设备原始报文直接透传至云端网关服务进行处理。

### 2.6 AI 综合赋能场景
- **核心AI（水务优先）**：用水量深度分析、用量预测、爆管等异常事件的提前主动预测。
  - **爆管预测核心模型**：基于 GIS 地理范围，综合分析**管网压力、瞬时流量、水质参数以及夜间最小流量（MNF）**等多维度指标的突变与趋势，建立高精度的漏损与爆管预测模型。
- **通用AI场景**：能耗趋势预测、设备预测性维护、安防与工业视频监控视觉分析。
- **大模型赋能与智能调度 (AIGC)**：
  - **基于大模型的知识问答与操作助理**：接入国产大模型（如通义千问、文心一言等），投喂历史工单、设备说明书与专家经验库。系统操作员可通过自然语言直接对话：“查询某车间昨日异常耗水原因”或“生成2号泵房故障维修建议”，大模型将直接生成指导性意见。
  - **智能调度策略生成**：在发生严重爆管或大规模停电等紧急态势时，大模型基于当前资源分布（在岗人员位置、备件库存）、历史处理成功案例及环境气象数据，自动生成**多套可行的应急抢修与调度预案（包含人员指派建议、设备切换步骤）**供管理者决策。

### 2.7 系统边界与商业权益保护机制
- **系统核心边界（非计费系统）**：本平台聚焦于工业综合治理中的**“用量统计、数据分析与态势展示”**，通过分析辅助决策。平台**坚决不涉及计费、费用结算与财务资金流**，以避免引入高昂的数据回滚、冲账及合规性风险。
- **系统安全**：全方位的平台安全防护策略（网络、数据传输、应用访问等）。
- **商业权益保护（防欠款策略）**：采用**动态 License 授权码**机制。该机制仅在应用层（如 Web 页面访问、手动下发反控指令）进行拦截与弹窗提示，**绝不影响底层主干业务计算、数据采集及核心流式清洗任务**的正常运行。

### 2.8 复杂真实业务边缘场景 (Edge Cases) 容错与闭环机制
针对水务及工业现场极度复杂的现实状况，系统必须具备以下兜底与容错处理能力，防止理想化模型在真实场景中失效：

- **营收与售水数据的深度对齐（解决“错期”与“估抄”）**：
  - **抄表周期错位分摊（日历对齐）**：供水数据是“自然月”，而营收售水多为“抄表月”（如跨月抄表、双月抄表）。系统内置分摊算法，将跨月账单水量按天数权重，或按该区域供水趋势权重，动态折算平摊到对应的自然月/日，避免产销差出现“假漏损”或“负漏损”。
  - **估抄水量与追溯重算（Recalculation）**：当营收系统因水表损坏或无法入户产生“估抄水量”时，标记为非置信数据。待未来获取真实读数（或换表补交）后，数据中台需支持一键触发“历史产销差重算”，自动修正过去数月的漏损指标。
- **合法未计费水量的“豁免/冲销”机制**：
  - 针对市政消防取水、环卫绿化洒水、管网排污冲洗等“有供水无营收”的合法用水，建立**“未计费水量冲销工单”**。外勤人员现场提报取水量与照片，审批后，系统在计算该 DMA 产销差时，自动将其从“真实漏损（物理漏水）”中剥离，防止干扰暗漏排查决策。
- **动态拓扑时间切片（应对 DMA 边界变更）**：
  - 管网改造或边界阀门的临时开闭会导致 DMA 拓扑发生变化。系统需引入**“时空拓扑（Temporal Topology）”**模型。记录每一次拓扑变更的版本时间轴；当查询历史漏损时，系统严格使用“当时的历史拓扑快照”进行结算，而非最新拓扑。
- **资产变更的数据连续性（换表/拆表补偿）**：
  - 当发生水表更换时（老表止码很大，新表起码为0），系统强关联“换表工单”。数据清洗引擎自动介入执行分段接续算法：`本期用量 = (老表拆除止码 - 上期读数) + (新表当前读数 - 新表安装起码)`，从根本上杜绝换表导致的负流量或数据断层。

## 3. 系统架构与技术选型规划

### 3.1 前后端架构设计
- **前端架构与可视化大屏**：
  - **单体大前端底座**：采用 **Vue3/React + TypeScript**，结合微前端设计思路，将管理后台与监控面板融合在统一的大底座中，保证权限体系一致性。
  - **可折叠 2D 拓扑全景图（革新树形结构）**：摒弃传统的左侧层叠树结构管理方式。针对站点、设备、DMA分区等层级，提供基于 2D 平面的全景逻辑拓扑组件。用户可通过鼠标滚轮缩放画布、点击父节点“折叠/展开”其下辖子站点或设备，以“网络拓扑/思维导图”的直观形态展现错综复杂的从属与水力流向关系。
  - **数字孪生与大屏监控（重点）**：利用 WebGL/Three.js 或国产数字孪生引擎（如 ThingJS 等）构建厂区级三维大屏，实现 BIM 模型导入、设备状态的三维挂载与实时动画反馈。
  - **高性能流式渲染**：针对大屏上万级别设备测点的数据高频推送（如 WebSocket 毫秒级刷新），前端引入 `requestAnimationFrame` 机制和 Canvas 离屏渲染，保障浏览器帧率（FPS）稳定，避免大屏卡顿卡死。
  - **动态组态与可视化编排**：内置零代码/低代码的可视化组态工具，允许业务人员通过拖拽图表组件、管道元件，自定义各个车间或工艺流程的 2D/2.5D 监控面板。
- **后端架构**：采用基于 **NestJS** 框架的分布式微服务架构。
  - **服务拆分原则**：按大业务领域进行粗粒度拆分，如“报警中心服务”、“数据中台服务”、“设备接入网关服务”、“业务调度服务”等。
  - **部署与扩容**：各个微服务完全解耦，支持根据业务负载进行**独立的服务器部署与横向扩容**（例如，在数据洪峰时单独为“数据中台服务”增加服务器）。
  - **服务治理**：利用 **Redis** 作为核心的服务注册中心与状态监控中枢。
  - **高可用与自愈**：各微服务通过 Redis 维持心跳，当监控到服务超时或无响应时，触发自动重启/熔断机制，保障系统在复杂工业环境下的极高可用性。

### 3.2 信创适配要求
- **底层硬件**：暂无特定厂商要求，保持通用性与可扩展性。
- **操作系统**：以 **麒麟操作系统（Kylin）** 为主。
- **数据库（解耦设计）**：
  - **基础业务库**：采用 **PostgreSQL (PG)** 存储设备台账、组织架构、业务配置等关系型基础数据，方便后续向其他纯信创关系库平滑移植。
  - **时序与大数据库**：采用 **独立的时序数据库（如 TDengine / IoTDB 等）** 专职处理百亿级高频时序监控数据，并充分利用其内置流计算能力进行降采样与清洗聚合。
- **缓存与中间件**：
  - **Redis**：不仅用于业务缓存，更作为后端微服务的心跳监控与服务注册中枢。
  - 按需引入其他主流信创组件。
